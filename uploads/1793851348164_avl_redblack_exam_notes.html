Balanced Search Trees: AVL Trees & Red-Black Trees – Exam Notes

1. Balanced search trees (overview)

Plain BSTs can degenerate into a linked list, so balanced variants keep the height near log n. The lecture lists: AVL trees, 2-3 trees, 2-3-4 trees, B-trees and Red-Black trees. This lecture covers AVL and Red-Black in detail.

2. AVL tree

  • An AVL tree is a self-balancing binary search tree: it is a BST that is also a balanced tree.
  • The balance factor of every node is no more than 1 (in absolute value).
  • The balance factor is often stored in each node, but can also be computed from the heights of the subtrees.
  • Each node keeps track of the height of the subtree rooted at it. The AVL property is maintained using rotations, which are applied when an insertion or deletion unbalances the tree.
Balance factor = height of left subtree − height of right subtree
Valid values: −1, 0, +1. If any node has another value (e.g. 2 or −2) the tree is not balanced and is not an AVL tree.

In other words: a tree is balanced if, for every node, the heights of its two children differ by at most one.

Key fact: Every AVL tree is a binary search tree, but not every BST is an AVL tree.

3. Maintaining balance

  • Inserting a node can increase the height of a tree by at most 1.
  • Removing a node can decrease the height of a tree by at most 1.
  • Example: in the tree 36 → (12, 44), 12 → (7, 17), 7 → (3, 10), 17 → (·, 27), 44 → (38, 45), inserting 15 as the left child of 17 does not change the height of any subtree, so the tree stays balanced and no rotation is needed.

4. Insertion and rotation in AVL trees

  • An insert can make a balance factor become 2 or −2 for some nodes.
  • Only the nodes on the path from the insertion point up to the root can have changed height.
  • So after the insertion, go back up node by node to the root, updating heights.
  • If a new balance factor is 2 or −2, fix it by a rotation around that node.
  • After every insertion or deletion, check the balance factor of the nodes. If all satisfy the condition the operation is finished, otherwise the tree must be rebalanced.
Rotation is the process of moving nodes to the left or right to make the tree balanced.

5. The four rotations

There are four rotations in two types: single rotations (Left = LL, Right = RR) and double rotations (Left-Right = LR, Right-Left = RL).

Naming in this lecture: “LL rotation” means a single left rotation (nodes move one position left) and “RR rotation” means a single right rotation. Many textbooks name rotations by the imbalance case instead, so use the lecture's names in the exam and state what the rotation does.
RotationWhen (imbalanced shape)What it does
LL (single left)Inserted a longer chain on the right (e.g. insert 1, 2, 3; node 1 has factor −2)Every node moves one position to the left; the middle node becomes the root.
RR (single right)Chain on the left (e.g. insert 3, 2, 1; node 3 has factor +2)Every node moves one position to the right.
LR (double)Left child has a right child (insert 3, 1, 2; node 3 has factor +2, zig-zag)First a left rotation on the left child, then a right rotation on the unbalanced node.
RL (double)Right child has a left child (insert 1, 3, 2; node 1 has factor −2, zig-zag)First a right rotation on the right child, then a left rotation on the unbalanced node.

6. Operations on an AVL tree

Three operations: search, insertion, deletion.

Search (same as BST search)

  1. Read the search element.
  2. Compare it with the value of the root node.
  3. If they match, display “Given node found” and stop.
  4. If not, check whether the search element is smaller or larger than the node value.
  5. Smaller → continue in the left subtree. Larger → continue in the right subtree.
  6. Repeat until the exact element is found or a leaf is reached.
  7. If the node with the search value is reached → “Element is found”. If a leaf is reached and does not match → “Element not found”.

Insertion (time complexity O(log n))

A new node is always inserted as a leaf.

  1. Insert the new element using normal BST insertion logic.
  2. After insertion, check the balance factor of every node.
  3. If every balance factor is 0, 1 or −1, go to the next operation.
  4. If any balance factor is not 0, 1 or −1, the tree is imbalanced: perform the suitable rotation to rebalance, then go to the next operation.

Deletion

  • Deletion is similar to BST deletion (no child, one child, two children with in-order predecessor/successor).
  • After every deletion, check the balance factor condition.
  • If balanced, go to the next operation; otherwise perform the suitable rotation.

10. AVL exam checklist

  1. Insert the key as in a BST (as a leaf).
  2. Walk back up to the root, updating heights and balance factors.
  3. At the first node with factor ±2, identify the shape: straight line (single rotation) or zig-zag (double rotation).
  4. Rotate, then re-check all nodes. Draw the tree after each rotation.

11. Red-Black tree

  • A Red-Black tree is another variant of the binary search tree in which every node is coloured either RED or BLACK.
  • In AVL trees, balancing restricts the difference in heights to at most one. In Red-Black trees a different set of rules about the colours of the nodes keeps the tree balanced.

The six properties

#Property
1A Red-Black tree must be a Binary Search Tree.
2The root node must be coloured BLACK.
3The children of a red node must be black (no two consecutive red nodes).
4On all paths of the tree there must be the same number of black nodes.
5Every new node must be inserted with RED colour.
6Every leaf (i.e. NULL node) must be coloured BLACK.
Memory aid: Root black · no red-red parent/child · equal black count on every path · new nodes red · NULL leaves black.

“Is this a Red-Black tree?” (slide exercise)

The slide shows a tree rooted at 19 with red nodes 12, −5, −6, 50, 135 and 80. To decide, check the properties:

  • No red node has a red child, so property 3 holds.
  • Count black nodes along different paths: the path 19 → 35 → NULL has far fewer black nodes than the path through 12, 0, −10, … so property 4 fails and the tree is not a valid Red-Black tree.

Also note the two example Red-Black trees on the slide: every node satisfies all properties, with black root and equal black counts down every path.

12. Insertion into a Red-Black tree

  • Insert like a BST, but give the new node the colour RED.
  • After every insertion check all the properties. If all hold, move on to the next operation; otherwise fix the tree using one of: Recolour, or Rotation followed by recolour.
  1. Check whether the tree is empty.
  2. If empty, insert the new node as the root with colour BLACK and exit.
  3. If not empty, insert the new node as a leaf with colour RED.
  4. If the parent of the new node is black, exit.
  5. If the parent is red, check the colour of the parent's sibling (the “uncle” of the new node).
  6. If the uncle is black or NULL → make a suitable rotation and recolour.
  7. If the uncle is red → recolour and re-check (repeat upward) until the tree is a Red-Black tree.
The reason it works: a new red node can only break property 3 (red parent). A red uncle can be fixed by recolouring and moving the problem upward; a black or NULL uncle needs a rotation, which ends the problem.
