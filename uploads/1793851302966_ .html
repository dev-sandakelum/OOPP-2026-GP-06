Circular Linked Lists, and Stack & Queue Implementation Using Linked Lists

A complete, exam-focused review of circular linked list structures and how linked lists power dynamic stacks and queues.

1

Key Concepts & Definitions

TermDefinition
Circular linked listA linked list in which the last node's pointer holds the address of the first node instead of NULL. As a result, the list has no fixed beginning or end.
Circular doubly linked listA circular list where every node stores two pointers — next (successor) and prev (predecessor) — and both pointers wrap around circularly.
START (or HEAD)An external pointer variable that marks the entry point into the list. It is not a node itself — it simply stores the address of whichever node the list currently starts traversal from.
NodeThe basic building block: struct node { int info; struct node *next; }; — identical in a linear or circular list.
Stack (LIFO)A structure where the last element inserted is the first one removed. Implemented here with a single top pointer.
Queue (FIFO)A structure where the first element inserted is the first one removed. Implemented here with a front and a rear pointer.
2

The Circular Linked List

A circular linked list is one which has no beginning and no end. A singly linked list is converted into a circular one simply by storing the address of the very first node inside the next field of the last node, rather than leaving it as NULL.

Figure 1 — Singly circular linked list. START points to node 10; node 50's next field wraps back to node 10.
Common exam trap

Do not confuse the struct definition with the wiring. The node structure for a circular list is written exactly the same way as for a linear list — struct node { int info; struct node *next; };. What makes it "circular" is only what address gets stored in the last node's next field at run time.

3

Circular Doubly Linked List

A circular doubly linked list has both a successor pointer (next) and a predecessor pointer (prev), and both are arranged circularly. This means you can traverse the list in either direction, and from any node you can reach any other node.

Figure 2 — Circular doubly linked list. Each node holds prev | data | next; both ends wrap around.

Advantages of Circular Linked Lists

  1. Any node can be a starting point. You can traverse the whole list starting from any node — you simply stop once the first node you visited is reached again. There is no dependency on always starting at a fixed "head."
  2. Efficient queue implementation. Unlike an array-based or linear-list-based queue, a circular linked list only needs one pointer (to the last inserted node); the front of the queue is always obtainable as next of that last node, instead of maintaining two separate front/rear pointers.
  3. Ideal for repeatedly cycling through a list. Useful whenever a program needs to go around a set of items again and again — for example, an operating system giving each running application a time slice, in turn, forever.
Connecting the dots

Advantage 2 is a preview of Sections 6–7: the array-based queue idea of tracking front and rear reappears later when we build a queue from a linear linked list — except there we do keep both pointers, because a linear list's last node has no way to point back to the front. A circular list removes that need.

Applications of Circular Linked Lists

ApplicationHow the circular structure is used
Operating systems (round-robin scheduling)Multiple running applications are kept in a circular list. The OS gives each one a fixed time slice and cycles through them; when it reaches the end of the list it automatically loops back to the front — no special-case code needed.
Multiplayer gamesPlayers are stored in a circular linked list; a pointer moves forward to the next player as each player's turn ends, wrapping back to the first player after the last.
Circular queuesA circular linked list can implement a queue while needing only one pointer in memory (to the rear), instead of the two (FRONT and REAR) a plain queue needs.

Implementing a Circular Linked List

Implementation is almost identical to a linear linked list. The only difference: the last node's next is made to point to the head of the list, instead of holding NULL.

Why Use a Linked List for a Stack / Queue?

Before building stacks and queues out of linked lists, it's worth understanding the motivation: arrays have a hard limitation that linked lists solve.

Array-based stack/queueLinked-list-based stack/queue
CapacityFixed — must be declared in advanceUnlimited — grows and shrinks as needed
Size planningYou must know (or guess) the maximum size beforehandNo need to fix a size at the start
Wasted memoryPossible, if the array is over-sized "just in case"None — a node is allocated only when a value is added
Failure mode"Stack/queue overflow" if capacity is exceededLimited only by available system memory
Key idea

A linked-list-based stack or queue can organize as many data values as needed, because each new element is a freshly allocated node linked in with a pointer, rather than a slot in a pre-sized block of memory.

Shared building block

Both the stack and the queue in the next two sections reuse the same basic node:

struct node
{
    int data;
    struct node *next;
};
typedef struct node node;

What differs between them is only how many external pointers are used to manage the list, and at which end insertion/removal happens:

StackQueue
DisciplineLIFO — Last In, First OutFIFO — First In, First Out
External pointer(s)One: topTwo (+count): front, rear
Insert (add) atHead of list (becomes new top)Rear (tail) of list
Remove atHead of list (current top)Front (head) of list

Stack Implementation Using a Linked List

In a linked-list stack, every new element is inserted as the top element, and the top pointer always points to the most recently inserted node.

Figure 3 — Stack as a linked list. Insertion order was 25, 32, 50, 99; top points to 99 before push(10) is called.

Setup

struct node
{
    int data;
    struct node *next;
};
typedef struct node node;
node *top;

void initialize()
{
    top = NULL;
}

push(value) — insert at the top

  1. Create a new node.
  2. Set the new node's data to the given value.
  3. Point the new node's next to the current top.
  4. Move top to point to this new node.
void push(int value)
{
    node *tmp;
    tmp = malloc(sizeof(node));
    tmp -> data = value;
    tmp -> next = top;
    top = tmp;
}

pop() — remove and return the top element

  1. Make a temporary node pointer.
  2. Point it to the current top.
  3. Store the temporary node's data in a variable.
  4. Move top to the next node in the list.
  5. Free the temporary node's memory.
  6. Return the stored value.
int pop()
{
    node *tmp;
    int n;
    tmp = top;
    n = tmp->data;
    top = top->next;
    free(tmp);
    return n;
}
Top() 
int Top()
{
    return top->data;
}
isempty() 
int isempty()
{
    return top==NULL;
}
Watch out

The pop() code above does not check isempty() first. If pop() is called while top == NULL, the line n = tmp->data; dereferences a null pointer. In practice (and often in exam "spot the bug" questions), you should call isempty() before popping.

Queue Implementation Using a Linked List

A queue needs to track both ends of the list, because new items are added at the rear while items are removed from the front. The queue is wrapped in its own structure holding a node count plus front and rear pointers.

Figure 4 — Queue structure: front points to the head (A), rear points to the tail (C).

Setup

struct node
{   int data;
    struct node *next;
};
typedef struct node node;

struct queue
{   int count;
    node *front;
    node *rear;
};
typedef struct queue queue;

void initialize(queue *q)
{
    q->count = 0;
    q->front = NULL;
    q->rear  = NULL;
}

isempty() — check based on rear

The queue is empty exactly when rear (equivalently front) is NULL:

int isempty(queue *q)
{
    return (q->rear == NULL);
}

enqueue(value) — insert at the rear

  1. Create a new node and set its data.
  2. If the queue is empty, point both front and rear to this new node.
  3. Otherwise, link the current rear's next to the new node, then move rear to it.
  4. Increment count.
void enqueue(queue *q, int value)
{
    node *tmp;
    tmp = malloc(sizeof(node));
    tmp->data = value;
    tmp->next = NULL;
    if(!isempty(q))
    {
        q->rear->next = tmp;
        q->rear = tmp;
    }
    else
    {
        q->front = q->rear = tmp;
    }
    q->count++;
}

dequeue() — remove and return the front element

  1. Make a temporary node pointer.
  2. Point it to the current front.
  3. Store front->data in a variable.
  4. Move front to the next node.
  5. Decrement count and free the temporary node.
  6. Return the stored value.
int dequeue(queue *q)
{
    node *tmp;
    int n = q->front->data;
    tmp = q->front;
    q->front = q->front->next;
    q->count--;
    free(tmp);
    return(n);
}
9

Connections Between the Ideas

  • One node struct, three behaviours. The circular list, the linked stack, and the linked queue all use the same minimal struct node { data; next; }. The "personality" of each structure comes entirely from how external pointers (START, top, or front/rear) are managed, not from a different node design.
  • Circularity as an efficiency trick for queues. A linear-list queue needs two external pointers (front and rear) because, once you reach the last node, there is no way back to the first. A circular list sidesteps this: the last node already points to the first, so only one external pointer (to the last-inserted node) is required — the "front" is just next of that node.
  • Insertion/removal end defines the discipline. Stack = insert and remove at the same end (the head) → LIFO. Queue = insert at one end (rear), remove at the other (front) → FIFO.
  • All core operations are O(1). Because every operation (push, pop, enqueue, dequeue) only touches a fixed number of pointers near the head/tail — never a search through the whole list — each runs in constant time, regardless of how many elements are stored.
  • Both solve the same underlying problem as circular lists: avoiding a fixed, pre-declared capacity. Arrays force a size decision upfront; every structure in this lecture (circular list, linked stack, linked queue) instead grows one node at a time via malloc.

Practice Questions

Q1.In a circular linked list, what does the next pointer of the last node contain?
  • (a) NULL
  • (b) The address of the first node
  • (c) The address of the previous node
  • (d) A garbage value
Answer(b) — that single change (replacing NULL with the first node's address) is what defines a circular list.
Q2.True or False: A circular linked list must always be traversed starting from one fixed, unchangeable node.
AnswerFalse. Any node can serve as a starting point — you traverse forward and simply stop when you revisit the node you started from.
Q3.Give two advantages of a circular linked list over a linear linked list, each with a real-world example.
Answer(1) Any node can be a start point — useful for iterating repeatedly, e.g. cycling through running applications on an OS. (2) A queue built on a circular list needs only one external pointer (to the last node), since "front" is simply that node's next — more memory-efficient than tracking separate front/rear pointers.
Q4.In the linked-list enqueue() function, what happens to q->front when the queue was empty before the call?
AnswerBoth q->front and q->rear are set to the newly created node: q->front = q->rear = tmp;
Q5.Why does isempty(queue *q) check q->rear == NULL rather than q->front == NULL?
AnswerEither check works — front and rear become NULL together (on initialize()) and become non-NULL together (on the first enqueue()). The slide simply adopts rear as its convention.
Q6.What is the time complexity of push() and pop() in a linked-list stack?
  • (a) O(n)
  • (b) O(log n)
  • (c) O(1)
  • (d) O(n²)
Answer(c) O(1) — both only rewire a fixed number of pointers at the top; no traversal of the list is needed.
Q7.Fill in the blank: in push(), the line ______ makes the new node point to the current top, before top itself is updated.
Answertmp -> next = top;
Q8.Explain, step by step, what pop() does and why free(tmp) is necessary.
AnswerIt saves the current top in a temporary pointer, reads its data, advances top to top->next, then deletes the old top node with free(tmp) — releasing its memory back to the system so it isn't leaked — and finally returns the saved value.
Q9.Why is a linked list generally preferred over an array for a stack/queue when the number of elements is not known in advance?
AnswerAn array needs a fixed capacity declared upfront — too small risks overflow, too large wastes memory. A linked list allocates one node per element on demand, so it can grow (or shrink) to exactly the size needed, limited only by available memory.
Q10.In enqueue(), which two lines link a new node C into a non-empty queue and update rear?
Answerq->rear->next = tmp; followed by q->rear = tmp;
Q11.How does a circular doubly linked list differ structurally from a singly circular linked list holding the same nodes?
AnswerEach node additionally stores a prev pointer, and the prev chain also wraps circularly (the first node's prev points to the last node). This allows traversal in both directions, at the cost of one extra pointer per node.
Q12.Give one additional real-life example each for: (a) a circular linked list, (b) a stack, (c) a queue.
Answer(a) Round-robin CPU/process scheduling or a multiplayer game's turn order. (b) An editor's "undo" history, or a program's function call stack. (c) A printer's print job queue, or a call-centre's hold line.

Key Takeaways & Exam-Style Points

  • 01Circular list: last node's next = first node's address, not NULL.
  • 02No fixed start/end → traversal can begin anywhere; stop on revisiting the start.
  • 03Circular doubly linked list wraps both next and prev.
  • 04The struct node definition is identical for linear and circular lists.
  • 053 advantages: any-node start, single-pointer queues, repeated cycling (OS/games).
  • 06Applications: OS scheduling, multiplayer turn order, circular queues.
  • 07Linked stack = LIFO, one top pointer, O(1) push/pop, no traversal.
  • 08push: malloc → set data → tmp->next=top → top=tmp.
  • 09pop: save top → advance top → free old node → return saved value.
  • 10Linked queue = FIFO, needs front, rear, and a count.
  • 11enqueue has two cases: empty (set front=rear) vs. non-empty (link rear, move rear).
  • 12dequeue always removes from front and frees the old front node.
Gaps in the source material — good to know before the exam
  • The slides do not state formal time/space complexity — this guide adds it (all core operations are O(1)).
  • Neither pop() nor dequeue() in the slides checks isempty() first; calling them on an empty structure would dereference a NULL pointer.
  • A circular queue is mentioned as an application but its actual code is not shown in the slides.
  • No worked numeric trace of a full enqueue/dequeue sequence is given — practice tracing Q4/Q10 by hand with your own values.
